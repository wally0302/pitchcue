# 揪甘心知識蒸餾 Prompt 設計

日期：2026-10-02

## 目標

提供一份可直接貼入 ChatGPT 的 Prompt。使用者會同時附上最新版「揪甘心」簡報，ChatGPT 必須一次完成知識蒸餾，產出能直接放進 PitchCue 的多檔案知識包。

## 使用流程

1. 使用者開啟保存「揪甘心」資訊的 ChatGPT 對話或專案。
2. 貼上本 Prompt，並附上最新版簡報內容。
3. ChatGPT 使用當前對話實際可取得的內容、可用記憶與附件，一次產出完整知識包。
4. ChatGPT 不追問、不等待確認；缺少資料時寫明「目前未提供」。
5. 使用者將各程式碼區塊另存成對應檔名，放入產品知識目錄。

## 輸出檔案

```text
00-單一真相與回答規則.md
01-產品簡介與定位.md
02-使用者與產品流程.md
03-市場需求與驗證.md
04-商業模式與成長策略.md
05-功能與技術架構.md
06-現況限制與Roadmap.md
07-評審常見問題.md
glossary.txt
```

每份文件使用獨立程式碼區塊，區塊前只顯示檔名。輸出完成後不追加摘要、建議或說明。

## 蒸餾原則

- 最新簡報優先於舊資料；更明確、更新、較保守的說法優先。
- 不假裝讀過無法存取的其他聊天。
- 合併重複資訊，同一事實只保留一致版本。
- 口播與舞台提示不當成產品事實。
- 保留數字、假設、公式、流程、角色、產品邊界、現況和下一步。
- 不把願景、規劃、估算或目標寫成已完成成果。
- 不捏造訪談、使用者、營收、合作、準確率、技術實作或外部來源。
- 衝突資料採用一個現行版本；過時說法放入「禁止使用說法」。
- FAQ 使用「直接回答、證據或理由、限制、下一步」結構。
- 排除密碼、API Key、憑證、私人聯絡方式與不必要個資。
- glossary 每行一個容易被語音辨識錯誤的詞，不附解釋。

## 方案選擇

採用雙層知識包：`00` 至 `06` 保存完整產品事實，`07` 轉成現場評審 FAQ。相較純摘要或純 FAQ，這能兼顧回答的事實基礎與現場可用性，同時維持簡單的一次產出流程。
