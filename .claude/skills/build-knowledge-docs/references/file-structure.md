# 八份文件的結構

| 檔名 | 目標字元 | 必要區塊 |
|---|---:|---|
| 00-回答規則與數字速查.md | 4–5k | 回答時的固定原則（含名稱、定位、人物稱呼）／絕對不要說的話（❌→✅ 表）／數字速查表（項目、值、標籤與附註）／已解決的版本衝突／文件裡沒有的東西 |
| 01-專案簡介與定位.md | 1.5–2k | 一句話／要解決的問題（數字出處）／誰在用、誰做決定／貫穿原則／這次做出來的範圍／刻意沒做、要主動講的／跟現成工具的差別／團隊 |
| 02-核心流程與人機分工.md | 3–4k | 一句話／各階段誰做什麼（表）／為什麼要人確認／每階段的細節與踩過的坑／稽核／範圍外 |
| 03-架構與技術決策.md | 3–4.5k | 一句話／服務清單與角色／關鍵設計為什麼／模型選擇（含沒做什麼評測）／刻意不用的與理由／規則限制與破口／踩過的坑／安全現況誠實版／怎麼部署／可觀測性／範圍外 |
| 04-資料處理與檢索.md | 3–4k | 一句話／資料怎麼切（表）／為什麼這樣設計／踩過的坑／演算法與門檻／門檻可信度表／資料集限制／目前有沒有量測／範圍外 |
| 05-Demo案例與現場測試.md | 2–4k | 一句話／demo 案例各展示什麼／現場要跑要多久與條件／評審遞新輸入時怎麼回（可做／不能假裝）表／最有說服力的操作／已知現場故障症狀／不要在現場做的事／簡報逐頁可能被追問的點／範圍外 |
| 06-已知限制與後續規劃.md | 2–3k | 一句話／我們自己列的缺口（分類）／命題要求但沒做／成本／個資、落地與導入／競品與定位（標明未並排實測）／下一步順序／範圍外 |
| 07-常見問題.md | 7–9k | 依評分面向分組：主題切合度／應用性／技術可行性／完成度／創意度／挑戰與質疑／即席測試／針對簡報畫面的追問／希望評審記住的三件事 |

## 數字標籤

- `★實測（日期）`：程式或環境實際跑出來的。
- `估算：假設 X`：有算式、有假設，講的時候一定帶假設。
- `命題文件數字`：主辦給的，我們沒驗證。
- `目標值，未實測`：只有目標。
- `設定`：程式或設定裡的值。

## FAQ 每題格式

```
- 評審的問題？
  答：兩到三句，80 到 150 字。第一句就是結論。有數字就帶標籤。沒做的事講現況與下一步。
```

## 禁句表格式

```
| 不要說 | 改說 |
|---|---|
| 舊簡報或錯誤說法 | 正確版本，含為什麼 |
```
