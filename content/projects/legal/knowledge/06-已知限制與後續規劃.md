# 已知限制與後續規劃

## 一句話：缺口都是已知的、刻意留著的，不是漏看

我們自己的待辦文件把沒做的事分四類，每一項都標了為什麼和不做會怎樣。回答評審時先承認，再講現況與下一步。

## 我們自己列的缺口

**功能不完整**
- 附件圖片不做 OCR：圖片只保存與列出，不進檢索。刻意的階段性決定，選項是 Textract（不支援中文）、Bedrock 視覺模型或前端先做。
- 附件檢索只取前 1,500 字：長卷證後半段等於沒被檢索到。要做分段檢索，代價是 1 RPS 下每份多花好幾秒。
- 不受理案看不到訴願法條文原文：不受理草稿引用的 14、56、77 條是模板寫死的，承辦人要自己翻。接口已備好，實作時直接查條號不叫 AI。
- prompt 寫死在程式裡：設定表（規則、正名、欄位影響）可線上改，prompt 還不行。比賽前動這個風險高。
- 三個 API 前端沒接：承辦人修改階段結果、稽核軌跡頁面、單一設定檔讀取。稽核對這個系統特別重要，後端每步都在寫，只差前端。

**安全與合規**
- API Gateway 沒有認證：網址等於憑證。緩解是網址不進 git。收斂是 API Key 或 Cognito JWT。
- GUARDRAIL_ID 沒設：不設不會壞，8 道程式檢查照跑。設只要 5 分鐘。
- Bedrock 1 RPS 有破口：每實例各自限流，目前靠紀律不同時跑建庫和案件。

**資料與品質**
- 主張庫只有 69 條、母體 24 件，統計意義弱。
- 語料檔名帶「的副本」，功能沒問題但畫面看得到。
- 一件測試案處置矛盾（逾期卻選實體審查），系統正確地標了 need_human，但當 demo 素材會困惑。

**法律流程**
- 77 條第 7 款重行提起沒接案件管理系統。
- 款 1、4、5 的「經通知補正逾期不補」永遠到不了成立，因為卷內看不到補正紀錄。
- 寄存送達、公示送達、在途期間沒實作。
- 補正之後、撤銷之後只記狀態，沒有發函與收件。
- 同一案號不同訴之聲明各走各的路徑（施案那種部分駁回加部分不受理）沒做。

## 命題要求但我們沒做的

- 「標示法規最新修正狀態」：沒做。索引只有年份欄位，沒有公布、施行、修正日期，也沒有版本比對。計畫是加三個日期欄位，並在檢索結果標新舊法。
- 「推薦前 3 到 5 個最相似案例」：目前是段落級命中附案號，案件層級去重成 3 到 5 件還沒做。
- 承辦人拍照上傳全部卷證的情境：目前訴願書、答辯書要有文字層，整個解析流程沒有為圖片設計。

## 成本

目前沒有總成本或每件成本的數字。每次 AI 呼叫的模型、token 進出、毫秒數都記錄在 ai_calls，是可以加總的，只是還沒做。已知的成本設計：OpenSearch Serverless min OCU 設 0，閒置不收費，不設會一個月約 US$345；Lambda、DynamoDB、API Gateway 全部按用量；沒有任何常駐主機。計畫是把 ai_calls 加總，算出每件草稿的 token 成本，再對照承辦人省下的時間。

## 個資、資料落地與導入

- 比賽規定不能把個資匯入比賽帳號，所以 demo 用的是依決定書重建、去識別的模擬案卷（姓名都是○）。
- 真實導入時卷證含身分證字號等個資，要在市府自己的 AWS 帳號或指定區域，卷證不能離開市府環境。設計上已經考慮：所有資源可用腳本在任何帳號、任何區域重建；案件資料按案號隔離；未來 Cognito 上線後只有被指派的承辦人能讀該案。
- 定位是法制局內部系統，不是商品。導入路徑：先用去識別的歷史案卷讓承辦人盲測幾件、補認證與稽核頁面、再談上市府環境試辦。目前沒有採購或導入時程，這要法制局決定。
- 8 月會議定的界線：原處分機關永遠拿不到草擬功能；公開只看得到去識別決定書。

## 競品與定位

沒有做過並排實測，只能講設計差異：
- 通用聊天工具（ChatGPT 之類）：沒有引用範圍檢查、不會用程式算逾期、沒有稽核軌跡，寫出來的法條可能不存在。
- 法律檢索工具（Lawsnote、七法之類）：它們是找法條判決的工具，我們是有人工確認關卡的審案工作流，檢索只是第三階段。
- Bedrock Knowledge Base：混合檢索比例寫死，法律文字需要自己控制 BM25 與向量的門檻。
- 為什麼不容易照抄：難的不是模型，是 20 條檢核規則、77 條八款的程式與 AI 分界、8 道程式檢查、兩個索引的門檻，這些都是拿真實決定書一件一件對出來的。

## 比賽後的下一步（建議順序）

1. API 認證（API Key 最快，Cognito 正規）；repo 若轉公開這變必做。
2. 稽核軌跡頁面，決定書要能追溯每一次人工介入。
3. 設 Guardrail 的 contextual grounding，5 分鐘。
4. 用保留的 114 年 21 份決定書當測試集，量欄位擷取 exact match、檢索 Recall@5、分類 macro-F1，報 n。
5. 找法制局承辦人盲測 5 件，量實際省下的時間，取代 261 小時的估算。
6. 法規版本欄位與修正狀態標示。
7. 款 7 接案件管理系統；寄存、公示送達與在途期間。
8. 分段檢索、圖片 OCR 方向決定後再做。
