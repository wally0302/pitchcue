# 揪甘心｜商業模式與成長策略

## 1. 商業模式核心邏輯
目前商業模式不是「向使用者收成團費」，而是「第一階段免費驗證真實聚會需求；第二階段在使用者已成團、開始準備消費時，探索 B 端變現。」
一句話：「我們不是從『喬時間』收錢，而是免費取得真實聚會需求，再從『已成團、準備消費』這個高意圖節點探索變現。」

## 2. 第一階段為什麼免費
揪甘心目前仍是 MVP。如果使用、活動完成與回訪都還沒被驗證，就太早增加付費摩擦。因此核心成團功能先免費，目的不是永遠不收費，而是先驗證使用習慣。

## 3. 第一階段真正要驗證什麼
1. 主揪是否願意建立活動。
2. 參與者是否願意透過分享連結加入。
3. 活動是否真的能完成成團。
4. 主揪下一次是否再次使用。
5. 參與者未來是否可能轉成新的主揪。

## 4. 第一階段可以累積什麼
- 真實多人聚會需求
- 高頻主揪
- 自然帶入參與者
- 成團行為資料
這些是產品預期可累積的資產，不是已經有大量資料。

## 5. 第二階段
把聚會場景從單純聚餐延伸到：
- KTV
- 密室逃脫
- Party Room
- 活動體驗
- 住宿
- 其他具有較明確客單價與訂位行為的多人場景
這個階段才開始驗證主要商業模式。

## 6. 商業價值在哪個節點產生
不是「有人想約朋友」，而是「一群人已經成團，而且準備決定去哪裡消費」。這時需求比一般興趣廣告更接近交易。

## 7. 高意圖需求
例子：「8 個人／星期六晚上／台北／每人預算 800 元／想找 KTV。」
包含人數、時間、地點、預算與活動類型，因此比單純「這個人可能喜歡唱歌」更接近實際消費。目前尚未有商家付費數據驗證這個假設。

## 8. 為什麼可能由商家付費
目前假設是商家可能願意為「接近成交的多人需求」付費。
一般廣告可能知道一個人喜歡密室逃脫；揪甘心未來希望掌握的是「6 個人已經約好星期六晚上，而且正在找台北的密室逃脫」。
這仍是商業假設，目前沒有實際商家訪談或願付價格數據。

## 9. 商家付費曝光
第二階段待驗證模式之一：Sponsored／Featured Placement。
邏輯：當一組已成團使用者正在尋找特定地點、人數、預算與活動時，商家可以付費取得符合條件的曝光。
Sponsored 內容未來應清楚標示，不應偽裝成純 AI 推薦。
目前尚未正式商業化。

## 10. 訂位／活動成交導流
第二個待驗證模式：CPA／Referral／Commission。
流程假設：使用者透過揪甘心 → 前往合作商家／活動 → 完成訂位或購買 → 商家／合作平台支付導流或成交費。
目前沒有固定抽成比例、固定 CPA、已談妥 Referral fee、已完成訂位 API 或實際成交。

## 11. 初期如何驗證成交
可用：
- 專屬可追蹤連結
- 優惠碼
- 合作 Landing Page
目的：先確認揪甘心帶過去的人是否真的產生訂位或購買。
若證明導流有成交價值，再考慮訂位 API、平台合作與成交佣金。
目前資料沒有顯示上述追蹤機制已正式完成。

## 12. 第三階段
長期方向：平台化／社群版／B2B。
包含社團、系學會、讀書會、Meetup、公司活動、多活動管理、團體通知、Organizer Dashboard、商家供給、訂位、付款、優惠整合。目前均屬 Roadmap。

## 13. Growth Loop
1. 一位主揪建立活動。
2. 主揪分享連結。
3. 多位參與者第一次接觸產品。
4. 參與者完成一次成團體驗。
5. 部分參與者未來在自己的聚會成為主揪。
6. 新主揪再帶入下一批參與者。
循環：分享 → 使用 → 成團 → 再分享。

## 14. 為什麼免費與 Growth Loop 有關
若參與者必須下載 App、先付錢、建帳號或加入新系統，會增加第一次使用摩擦。第一階段讓參與者免登入，就是為了降低被主揪帶入產品時的阻力。

## 15. 核心 Growth 指標
- 主揪回訪率：建立過活動的主揪，之後是否再次建立活動。
- 活動完成率：建立活動後，有多少走到確認成團。
- 參與者轉主揪率：原本參加別人活動的人，之後是否自己發起新活動。
目前沒有實際數值。

## 16. 是否已經有營收
目前提供的資料沒有顯示揪甘心已經有營收。正確回答：「目前仍在 MVP 驗證階段，第一階段本來就不以營收為主要目標。」

## 17. 是否已有合作商家
目前沒有合作商家名單，不可自行宣稱已有餐廳／KTV／訂位平台合作或商家願意付費。

## 18. 是否已有成交
目前沒有訂位數、活動購買數、GMV 或成交佣金，因此不可宣稱已有成交成果。

## 19. 商業模式主要風險
- 免費有使用，不代表會長期回來 → 追蹤主揪回訪率。
- 成團需求不一定自然轉成消費 → 觀察成團後 AI 選餐廳／其他場景使用。
- 商家不一定願意付費 → 用專屬連結、優惠碼或合作頁驗證導流價值。
- 曝光與成交歸因困難 → 先用可追蹤導流工具。
- Sponsored 可能破壞 AI 信任 → 未來需清楚區分自然推薦與付費曝光。
- 需要足夠需求量才有 B 端價值 → Phase 1 的 Growth Loop 與回訪驗證很重要。

## 20. 歸因、推薦中立性與累積順序
### 歸因漏損
使用者看到餐廳或活動名稱後自行前往訂位，可能造成成交無法歸因。曝光型收入不依賴成交歸因；成交型則可用專屬連結、優惠碼、合作 Landing Page 或商家端核銷進行測試。目前尚未完成正式歸因系統。

### 推薦中立性
未來若驗證商家付費曝光，Sponsored／Featured 內容應明確標示，並與依使用者條件產生的自然推薦分開，不應偽裝成 AI 排序結果。

### 能力累積順序
長期假設的順序是先累積需求端的高頻主揪與成團行為，再驗證商家供給，最後才建立訂位、付款與交易能力。這是 Roadmap，不是目前已形成的網路效應。

## 21. 商業模式現行總結
Phase 1：FREE → 驗證成團習慣。
Phase 2：MONETIZE → 從高意圖聚會需求驗證商家曝光與成交導流。
Phase 3：SCALE → 建立多人活動的需求、供給與交易網路。
